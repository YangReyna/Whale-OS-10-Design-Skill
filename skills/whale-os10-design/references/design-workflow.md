# 大屏原型、UI 与验证方法

本文件是后续设计的方法和建议。项目已确认规则见其他参考文件；这里不新增 Whale OS 强制产品规范。

## 从场景到状态

明确目标用户正在观看、找内容还是配置设备，以及任务触发源：Home、播放中、信号源、快捷设置或首次开机。入口决定背景是否保留、操作可否中断、返回哪里。只追问影响方案的设备能力、业务约束或版本冲突，能够从当前文件推断的常规选择先完成。

任务流采用「触发 → 前置条件 → 用户决策/操作 → 系统反馈 → 完成或恢复」表达。先解决主任务及直接相关异常，不为了穷举而新增产品功能。跨 App、扫码到手机、网络连接等交接点注明控制权、等待状态与回到大屏的条件。

为关键状态记录：入口和默认焦点、当前选值、可见内容、操作模式、四方向目标、OK/BACK 结果、滚动偏移，以及必要的时间阶段。简单页面可以一张表；出现分支、模态层或异步恢复时再画状态图和对应画面。

## 大屏视觉与输入

先以项目当前模板建立 1920×1080 的设计工作面；实际渲染分辨率、缩放、dp/sp 和安全边距需结合系统平台。不要把移动端字号、触控面积或 hover 原样搬到电视。

- 用有限方向的可预测路径组织信息。相关控件沿清楚的横纵轴排列，减少进入主任务的按键数。
- 焦点与选值都应清楚；根据组件区分 Default、Focused、Selected/Active、Focused+Selected、Disabled、Editing、Pressed。并非每个组件都需要全部状态，但不能让状态语义混淆。
- 为焦点放大、描边、阴影和多语言换行保留空间。检查扩大的实际边界，而不只看组件外框。
- 模态框在打开时接管交互，并有退出路径；关闭时恢复合理焦点。非模态提示不应抢走正在操作的焦点，除非项目场景明确如此设计。
- 图像或视频背景上的文字要在明亮、复杂、低对比素材上都验证。关键反馈不只靠颜色区分。
- 输入优先考虑遥控器完成成本。扫码、手机协同或语音若是方案的一部分，仍应按产品要求设计不可用或退出分支；不擅自取消已有遥控器路径。

## 设备适配：共享与差异

本次 Figma 主要取证 TV 通用页面，未验证 Projector/STB 的专属完整流程。下表是后续需要检查的场景，不代表该产品已经具备功能。

| 设备 | 设计时应确认的差异 |
| --- | --- |
| TV | 调谐器/直播、HDMI 与电视音画、遥控器实际键、观看距离和边缘可见性 |
| Projector | 自动/手动对焦、梯形校正、安装/投射模式、亮度与环境光、调节时应保留的画面；只设计设备已支持的能力 |
| STB | 外接显示器与 HDMI 输出、分辨率/画幅、CEC 和音量/电源控制归属、直播能力按 SKU 确认 |

共享品牌、语义 token 和基本控件时，专属设置的入口、权限、进度、中断恢复与遥控器限制单独处理。不得从组件搜索出现“投影仪设计系统（测试）”推定它是已经批准的生产库。

## 验证与数据分析

在原型中从实际入口完整走到完成，再覆盖 BACK、边界、模态打开/关闭、重新进入和相关恢复。每个关键状态应有唯一、可见且可达的焦点；键盘模拟和遥控器真机验证分别记录。

以任务指标判断设计：成功率、完成时间、按键数、误入/回退次数、焦点丢失与错误恢复成功率。涉及联动或网络时再加首次可操作反馈时间、过期内容覆盖或恢复失败等指标。比较方案时保持任务、设备、素材和样本条件一致，说明样本量及限制；没有数据时只提出验证计划，不编造用户偏好、显著性或性能收益，也不预设普适的达标阈值。

远距可读性、投影环境光、低性能设备动画、屏幕边缘裁切和本地化要在对应环境检查。单张 Figma 截图只能证明布局观察，不能证明真机可用性或性能。

## 公开资料：外部参考，不覆盖项目标准

以下为 2026-11-09 查阅的 Android 官方资料。它们支持通用大屏方法，不能直接替代 Whale OS 系统级行为；尤其不能照搬 Google TV 的 Home、Back、助手或退出规则。

- [Focus system](https://developer.android.com/design/ui/tv/guides/styles/focus-system)：以焦点识别可操作元素，并利用视觉反馈表达当前所在位置。
- [Navigation on TV](https://developer.android.com/design/ui/tv/guides/foundations/navigation-on-tv)：方向键路径应直接、可预测，所有可操作控件应可达，任务应减少无用层级与按键。
- [Layouts](https://developer.android.com/design/ui/tv/guides/styles/layouts)：沿横纵轴组织布局；焦点扩大会影响控件间距；关键内容需要考虑 overscan。该文档采用 Android 的 960×540 MDPI/dp 体系，**不要将其数值不经换算套到本项目的 1920×1080 设计坐标**，也不要用它覆盖项目的 48/72/144 模板标注。
